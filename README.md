## JSON Structure

Each quiz entry is stored as a JSON object with the following fields:

| Field          | Type          | Description                                                                                   |
| -------------- | ------------- | --------------------------------------------------------------------------------------------- |
| `id`           | Number        | Unique identifier for the quiz entry. IDs are automatically generated by the database script. |
| `category`     | String        | Main category of the quiz, such as `Movies`, `Anime`, or `VideoGames`.                        |
| `sub-category` | String / Null | Optional sub-category of the quiz. Set to `null` when a sub-category is not required.         |
| `answer`       | String        | The correct answer to the quiz.                                                               |
| `questions`    | Array         | List of five clues ordered by difficulty.                                                     |

### Question Object

Each question object contains:

| Field   | Type   | Description                                                                      |
| ------- | ------ | -------------------------------------------------------------------------------- |
| `level` | Number | Difficulty level from 1 to 5. Level 1 is the hardest and Level 5 is the easiest. |
| `text`  | String | The clue presented to the player.                                                |

### Scoring

Points are **not stored in the JSON data** because they can be derived directly from the question's `level`.

The application determines the score based on the level at which the player answers correctly:

| Level | Difficulty | Points |
| ----- | ---------- | ------ |
| 1     | Hardest    | 50     |
| 2     | Hard       | 40     |
| 3     | Medium     | 30     |
| 4     | Easy       | 20     |
| 5     | Easiest    | 10     |

For example:

```python
points = {
    1: 50,
    2: 40,
    3: 30,
    4: 20,
    5: 10
}

score = points[level]
```

This keeps the JSON database focused on storing **quiz content**, while the application handles **game logic and scoring**.

## Database Organization

The database uses folders to organize quiz entries by category and sub-category.

```text
TRIVIARDLE-DATABASE/
│
├── Anime/
│   └── Anime.json
│
├── Movies/
│   ├── Marvel/
│   │   └── Marvel.json
│   │
│   └── DC/
│       └── DC.json
│
├── VideoGames/
│
├── README.md
│
└── script.py
```

The database entry script automatically detects existing categories and sub-categories and allows new ones to be created. It automatically generates the next available `id` and appends the new quiz entry to the appropriate JSON file.
